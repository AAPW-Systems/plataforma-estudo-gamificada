# Checklist de entrega dos artefatos SDD

## Estrutura

- [ ] A funcionalidade possui identificador e nome curto.
- [ ] Os links relativos entre os arquivos funcionam.
- [ ] Não há segredos, dados pessoais reais ou credenciais.
- [ ] Arquivos não aplicáveis foram removidos ou marcados com justificativa, sem seções vazias.

## Especificação

- [ ] A spec explica o problema e o resultado antes de falar de tecnologia.
- [ ] A história P1 pode ser demonstrada isoladamente.
- [ ] Sucesso, ausência, erro e limites relevantes têm comportamento definido.
- [ ] Requisitos e critérios de sucesso são observáveis.
- [ ] Decisões confirmadas estão separadas de suposições.

## Plano

- [ ] O plano corresponde à spec aprovada.
- [ ] Componentes possuem responsabilidades e interfaces claras.
- [ ] Dados, contratos, testes e operação foram considerados.
- [ ] Decisões técnicas relevantes possuem alternativas e justificativa.
- [ ] Exceções aos princípios do projeto estão explícitas.

## Tarefas

- [ ] As tarefas estão na ordem das dependências.
- [ ] Cada tarefa possui identificador, ação e caminho exato.
- [ ] Tarefas de história indicam `[US1]`, `[US2]` ou equivalente.
- [ ] `[P]` aparece somente em trabalho realmente independente.
- [ ] Testes e documentação estão incluídos no trabalho, não deixados implícitos.

## Rastreabilidade

- [ ] Cada requisito importante aparece em pelo menos um cenário ou teste.
- [ ] Cada história possui tarefas suficientes para implementação e verificação.
- [ ] Não há tarefa que implemente comportamento ausente da spec.
- [ ] O quickstart usa comandos verificados após a implementação.

## Revisão final

- [ ] Outra pessoa consegue entender a funcionalidade sem apresentação oral.
- [ ] O grupo consegue explicar uma decisão rejeitada e a razão.
- [ ] As limitações conhecidas estão registradas.
- [ ] O estado dos checkboxes corresponde ao trabalho verificado.
